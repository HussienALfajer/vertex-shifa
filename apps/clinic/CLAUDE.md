# apps/clinic

Vertex Shifa Clinic, the offline-first desktop app (ADR 0008, ADR 0021, layout ADR 0020): a React + Vite + TanStack Router renderer in an Electron shell, Arabic-first RTL (ADR 0018). Today it holds the identity of the installation from S02 (clinic registrations, device and user keys, the PIN and lock screen, staff sessions) and the online-only clinic setup screens of S01 (onboarding wizard, clinic and branch settings); no local database, sync client or packaging yet (S04 and its specs bring them). The clinic system is the desktop app only (ADR 0024): in a plain browser the renderer says to open the desktop app.

## Layout
- `src/main.tsx` mounts the router (routes preload on intent), TanStack Query and i18n, and wires the staff session into the API client (`startIdentity`); `src/routes/` holds thin file-based routes (TanStack Router; `src/routeTree.gen.ts` is generated by the Vite plugin on `dev` and `build`, committed, never edited or read); `__root.tsx` sets the identity gate (which holds the shell and, for a signed-in member, the tenant gate) and the error and not-found states.
- `src/features/<area>/`: the components, queries and forms of one area. The pattern to copy for an online-only screen is S01: `features/tenancy/` (`queries.ts`: query options and API calls; `tenant-gate.tsx`: the tenant loaded before any screen, `/setup` while onboarding, the read-only banner and the main navigation; the shared field groups and their pure draft rules with unit tests), `features/setup/` (the wizard) and `features/settings/` (forms that keep the `updatedAt` they started from and reload on `CONFLICT`).
- `src/features/identity/` (S02): `identity-gate.tsx` (no device bridge: "desktop app only"; no unlocked member: `/lock`, or `/welcome` on an installation registered nowhere; signed in: the member menu, the idle lock, the device's data refreshed once per start and connection, and the tenant gate); `session.ts` (device tokens signed by the registration's device key; the staff session opened with the member's user key and refreshed a minute before its access token expires; `lockSession`; what a refusal does: `DEVICE_REVOKED` wipes the registration and confirms the wipe, `ENROLLMENT_REVOKED` deletes the member's key, the others lock with their reason); `installation.ts` (the main process's view as a query with `networkMode: 'always'`); `flow.ts` (the sign-in in progress between its screens, ticket in memory only); `sign-in-api.ts`; the screens (welcome, sign-in with OTP and first sign-in, register, new PIN, lock, my account); `code-fields.tsx` (six digits: an OTP, or a PIN masked); `idle-lock.ts`.
- App-wide `src/components/` (shell with the theme toggle in a `PageContainer` and the member's controls before it, `unsaved-changes.tsx`: the router blocker and `beforeunload` behind `UnsavedChangesDialog`, `query-states.tsx`: loading, offline and error states of a screen's queries; `offline-notice.tsx`; `field-group.tsx`) and `src/lib/`: `i18n.ts`; `error-logging.ts` (errors logged by name only); `api.ts` (the typed `openapi-fetch` client and `unwrap`, which turns a refusal into an `ApiError` carrying its code only; `authorizeRequests` adds the staff session's access token to every request but the sign-in and device ones, which pass `x-device-token` or `x-sign-in-ticket` themselves); `api-schema.gen.ts` (the API's types, generated from `apps/api/openapi.json` by `test/api-schema.test.ts`, committed, never edited or read); `device.ts` (the typed device bridge, `window.vertexShifaDevice`); `error-text.ts` (a code's Arabic text); `query-client.ts`; `online.ts`; `map-config.ts` (the location picker's map from `VITE_MAP_*`, MapLibre's worker served as a file of the app); `staff-access.ts` (`meQuery` and what the screens show from the member's effective permissions and branches); `history-shortcuts.ts` (Alt+Left / Alt+Right, mounted in `__root.tsx`).
- `src/styles.css`: imports Tailwind CSS, the desktop typefaces (`@vertex-shifa/ui/fonts-desktop.css`) and the design system (`@vertex-shifa/ui/styles.css`, ADR 0018); `vite.config.ts` adds `vertexShifaWeb()` (the theme before the first paint, the fonts preloaded); the app holds no colors or spacing of its own. Components and the `VertexShifaMark` come from `@vertex-shifa/ui`; `components/state-card.tsx` is the card of the screen states. The favicon comes from `brand/logo/svg/` (`index.html`).
- `electron/main.ts`: the main process. One window with `contextIsolation`, `sandbox`, no `nodeIntegration` and the preload `electron/preload.cts` (CommonJS, as a sandboxed preload must be), which exposes one call, `window.vertexShifaDevice.call(method, input)`, on the IPC channel `device:call`; the main process answers it only from the renderer's own origin. New windows, webviews and navigation outside the renderer's origin refused; every permission denied; one instance only. The built renderer is served from `app://clinic/` (`electron/app-protocol.ts`, path containment, client routes get `index.html`, a strict CSP header whose `connect-src` adds only the origins of the API URL `VITE_API_URL` and the map URLs `VITE_MAP_STYLE_URL`, `VITE_MAP_TILES_URL` and `VITE_MAP_GLYPHS_URL`, read at start; MapLibre's worker is served from `'self'`, so no blob worker is allowed). `--dev-server=<url>` loads the Vite dev server, only when unpackaged and only on loopback HTTP (`electron/navigation.ts`).
- `electron/identity/` (S02, ADR 0021, ADR 0024): `installation.ts` (the installation's clinic registrations, never two to one clinic, each with its Ed25519 device key and its members' user keys; the PIN unwraps a member's key, and five wrong ones in a row, counted and written before the PIN is checked, disable it until an online password sign-in; the 7-day offline window measured from the later of the device clock and the highest time seen, and the clock warning; the unlocked member and their session tokens in memory, so a reload of the window keeps them; the wipe of one registration, its device key kept until the server confirms; calls run one at a time), `keys.ts` (Ed25519, and the user key wrapped by Argon2id 64 MiB / 3 passes and then by `safeStorage`), `state-file.ts` (one file in `userData/identity/`, sealed whole by `safeStorage`, replaced atomically), `ipc.ts` (every call's input checked with Zod, refusals answered as codes only), `bridge.ts` (the calls' types, shared by the renderer, the preload and the E2E). Without a real keystore (`safeStorage` unavailable, Linux `basic_text`) every call answers `STORAGE_UNAVAILABLE`.
- Configuration, read at build by Vite and at start by the main process: `VITE_API_URL` (the API's origin; unset, requests go to the renderer's own origin, which only the E2E uses) and the `VITE_MAP_*` URLs (`packages/ui/CLAUDE.md`).
- Unit tests sit next to the code (`electron/identity/test-support.ts`: a stand-in protector, a state store in memory, a cheap Argon2id cost); `test/` holds the generated-client drift test. `e2e/`: Playwright against `vite preview`, light and dark. The API is mocked in memory by `e2e/mock-api.ts` (the S01 routes, bodies validated with the contracts, every staff route behind a session) and `e2e/mock-identity.ts` (the S02 sign-in, device and session routes, signatures checked); the device bridge by `e2e/device-bridge.ts`, which runs the main process's own `Installation` in the test's process with a clock the test moves. `mockApi` signs the owner in on the device before the page opens unless `signedIn: false`. The preview server stands in for the app's local files: let a screen render before going offline, or its code fails to load.

## Rules
- Forms follow `packages/ui/CLAUDE.md` "Forms": `Form` + `FormFields` + `FormActions`, values in `useDraft`, Save disabled until a change with "Discard changes" beside it, `useUnsavedChangesGuard(dirty)` with its `dialog` rendered in the screen (`allowLeaving()` before a navigation the form starts after saving), success as a toast, notices under the actions. Every sub-page has a back action in its `PageHeader`.
- Closing or reloading the window with unsaved changes: the renderer holds `beforeunload`, and the main process asks "Stay" or "Leave without saving" on `will-prevent-unload` (`electron/unsaved-changes.ts`, texts from `packages/i18n`).
- Every text through i18next with keys from `packages/i18n` (`useTranslation('<namespace>')`); never a literal in a component. Numbers and dates through `Intl` with `formatLocale` from `@vertex-shifa/i18n` (Latin digits); times shown in `Asia/Damascus`.
- Design-system components and Tailwind utilities on semantic tokens only (`bg-surface`, `text-muted-foreground`); logical directions only (`ms-`, `pe-`, `start-`, `text-start`; in CSS `margin-inline-*`, `inline-size`…), no physical 3- or 4-value shorthands, no `translateX`, no color values: pinned by `packages/ui/src/conventions.test.ts`, which scans this app's `src/`. The window title comes from i18n too (`document.title`). Styles and fonts are files from `'self'`, so the CSP stays strict.
- Every screen has its loading, empty, error and offline states (ADR 0020). An error state never shows or logs the error's message: it may carry patient data (ADR 0016). `main.tsx` routes React's and the router's error hooks to `logErrorLabel` and redacts any `Error` passed to `console.error`/`console.warn`; log errors with `logErrorLabel`, never the error object or its message.
- The renderer is untrusted: it gets no Node access. Keys, the PINs' derived keys and (S04) the local database and sync live in the main process; the renderer reaches them only through the device bridge (ADR 0021), sending PINs in and getting public keys, signatures and views out. A new call is a method in `electron/identity/bridge.ts` with its Zod input in `ipc.ts`. Never loosen `contextIsolation`, `sandbox` or the CSP; a new origin (API, sync service) is added to `connect-src` explicitly.
- Identity: a ticket or a PIN never goes in a URL, on disk or in a log (the sign-in in progress lives in `flow.ts` memory). Signing in, registering, enrolling, "Forgot PIN" and re-enabling a PIN are online only; the PIN within the window, the idle lock and switching clinic work offline. Locking forgets the member's server state (every query but the installation's).
- Data comes from the local database and changes go through sync commands (ADR 0008). Configuration that changes only online (S01 setup) is server state through TanStack Query: while offline, queries pause, saving is disabled and nothing is queued. A refusal is shown by its code's text (`useErrorText`), never the server's message.
- An edit sends the `updatedAt` the form started from, not the latest one in the cache, so a background refetch never hides another editor's change; on `CONFLICT` the form reloads the record and says so.
- A save never waits for the connection: mutations run with `networkMode: 'always'` (`query-client.ts`), and a read inside a save uses `fetchNow`, so offline it fails at once and nothing is sent later on its own. A form is locked while its save runs, and the save's callbacks use the step and values it was sent with.
- A create whose answer was lost may have happened. The next save looks for it, and a record it finds is only shown to the owner, never overwritten on a guess: the owner saves again against its `updatedAt`. (An idempotent create with an id made on the device would remove the guess.)
- A change to `apps/api/openapi.json` fails `test/api-schema.test.ts` until the types are regenerated: `pnpm --filter @vertex-shifa/clinic exec vitest run -u test/api-schema.test.ts`.
- UI changes add or update the E2E RTL screenshots (light and dark) and are looked at before the PR.

Run: `pnpm --filter @vertex-shifa/clinic test` · E2E (after `build`): `pnpm --filter @vertex-shifa/clinic test:e2e` · dev: `pnpm --filter @vertex-shifa/clinic dev` (browser: the "desktop app only" state) and `pnpm --filter @vertex-shifa/clinic dev:electron` (Electron on the dev server) · built app: `pnpm --filter @vertex-shifa/clinic start`.
