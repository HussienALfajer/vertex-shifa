# apps/clinic

Vertex Shifa Clinic, the offline-first desktop app (ADR 0008, ADR 0021, layout ADR 0020): a React + Vite + TanStack Router renderer in an Electron shell, Arabic-first RTL (ADR 0018). Today it holds the identity of the installation from S02 (clinic registrations, device and user keys, the PIN and lock screen, staff sessions), the online-only staff, doctor profile, devices and security screens of S02, and the online-only clinic setup screens of S01 (onboarding wizard, clinic and branch settings); no local database, sync client or packaging yet (S04 and its specs bring them). The clinic system is the desktop app only (ADR 0024): in a plain browser the renderer says to open the desktop app.

## Layout
- `src/main.tsx` mounts the router (routes preload on intent), TanStack Query and i18n, and wires the staff session into the API client (`startIdentity`); `src/routes/` holds thin file-based routes (TanStack Router; `src/routeTree.gen.ts` is generated by the Vite plugin on `dev` and `build`, committed, never edited or read); `__root.tsx` sets the identity gate (which holds the shell and, for a signed-in member, the tenant gate) and the error and not-found states.
- `src/features/<area>/`: the components, queries and forms of one area. The pattern to copy for an online-only screen is S01: `features/tenancy/` (`queries.ts`: query options and API calls; `tenant-gate.tsx`: the tenant loaded before any screen, `/setup` while onboarding, the read-only banner; `clinic-nav.tsx`: the sidebar's links from the tenant's status, its branches and the member's access; the shared field groups and their pure draft rules with unit tests), `features/setup/` (the wizard) and `features/settings/` (forms that keep the `updatedAt` they started from and reload on `CONFLICT`; `security-screen.tsx`: idle-lock minutes and the clinical read scope, S02 screen 10).
- `src/features/staff/` (S02 screens 6–8): `queries.ts`; `access-draft.ts` (the permission editor's pure rules over the API's catalog: "from role", "added", "removed", what the limits keep out, the adjustments sent) and `practitioner-draft.ts`, both unit-tested; `access-fields.tsx` (roles, branch scope, permissions) and `practitioner-fields.tsx` (doctor profile fields, the photo uploaded at once); the screens: staff list, invite, member (status actions and access form), doctor profile (`/settings/staff/:id/profile` by the owner, `/me/profile` for the doctor). An `ALREADY_MEMBER` refusal, also where a lost invitation answer leads, names the member it found by phone. `src/features/devices/` (screen 9): the computers in scope; rename, revoke with a reason, remove a member; a change to this computer refreshes its registration at once (a revocation wipes it).
- `src/features/identity/` (S02): `identity-gate.tsx` (no device bridge: "desktop app only"; no unlocked member: `/lock`, or `/welcome` on an installation registered nowhere; signed in: the shell with the clinic's sidebar, the lock button and the member menu, the idle lock, the device's data refreshed once per start and connection, and the tenant gate); `session.ts` (device tokens signed by the registration's device key, for the sign-in; the staff session, which the main process opens and refreshes, its access token refreshed a minute before it expires; `lockSession`; the main process's `locked` event followed; what a refusal does: on `DEVICE_REVOKED` or `ENROLLMENT_REVOKED` the main process asks the server itself (`refreshDevice`) and wipes the registration or deletes the member's key on its own answer, then `confirmWipe` has it confirm the wipe; the others lock with their reason); `installation.ts` (the main process's view as a query with `networkMode: 'always'`); `flow.ts` (the sign-in in progress between its screens, ticket in memory only); `sign-in-api.ts`; the screens (welcome, sign-in with OTP, first sign-in and the forgotten password of an authorized reset (rule 16), register, new PIN, lock, my account; six-digit OTPs and PINs through `CodeField` from `@vertex-shifa/ui`); `idle-lock.ts` (on `performance.now()`, the sleep the main process measured counted as idle).
- App-wide `src/components/` (`app-shell.tsx`: `AppShell`, the `AppFrame` of a signed-in member, and `AuthShell`, the `AuthFrame` of the identity screens, the gate's states and the error state; `unsaved-changes.tsx`: the router blocker and `beforeunload` behind `UnsavedChangesDialog`, `query-states.tsx`: loading, offline and error states of a screen's queries; `offline-notice.tsx`; `field-group.tsx`) and `src/lib/`: `i18n.ts`; `error-logging.ts` (errors logged by name only); `api.ts` (the typed `openapi-fetch` client and `unwrap`, which turns a refusal into an `ApiError` carrying its code only; `authorizeRequests` adds the staff session's access token to every request but the sign-in and device ones, which pass `x-device-token` or `x-sign-in-ticket` themselves; `api`, for the screens, binds each request to the identity scope it was sent in, and `identityApi`, for `session.ts` only, does not); `identity-scope.ts` (the unlocked member's scope, ended by every change of identity: a member's requests are aborted and their answers, like the query client's promises, never settle for the next identity); `api-schema.gen.ts` (the API's types, generated from `apps/api/openapi.json` by `test/api-schema.test.ts`, committed, never edited or read); `device.ts` (the typed device bridge, `window.vertexShifaDevice`); `error-text.ts` (a code's Arabic text); `query-client.ts` (on every change of identity: every query but the installation's, `meta: installationMeta`, cancelled and removed, the previous member's mutations dropped and their callbacks never run); `online.ts`; `map-config.ts` (the location picker's map from `VITE_MAP_*`, MapLibre's worker served as a file of the app); `staff-access.ts` (`meQuery` and what the screens and the main navigation show from the member's effective permissions and branches); `format.ts` (dates and times in `Asia/Damascus` with Latin digits); `history-shortcuts.ts` (Alt+Left / Alt+Right, mounted in `__root.tsx`).
- `src/styles.css`: imports Tailwind CSS, the desktop typefaces (`@vertex-shifa/ui/fonts-desktop.css`) and the design system (`@vertex-shifa/ui/styles.css`, ADR 0018); `vite.config.ts` adds `vertexShifaWeb()` (the theme before the first paint, the fonts preloaded); the app holds no colors or spacing of its own. Components and the `VertexShifaMark` come from `@vertex-shifa/ui`; `components/state-card.tsx` is the card of the screen states. The favicon comes from `brand/logo/svg/` (`index.html`).
- `electron/main.ts`: the main process. One window with `contextIsolation`, `sandbox`, no `nodeIntegration` and the preload `electron/preload.cts` (CommonJS, as a sandboxed preload must be), which exposes one call, `window.vertexShifaDevice.call(method, input)`, on the IPC channel `device:call`, and `onEvent(listener)` for the main process's events on `device:event` (`locked`, `suspended`, `resumed` with the time asleep, from `powerMonitor`; `electron/power.ts`); the main process answers calls only from the renderer's own origin and sends events only to it. New windows, webviews and navigation outside the renderer's origin refused; every permission denied; one instance only. The built renderer is served from `app://clinic/` (`electron/app-protocol.ts`, path containment, client routes get `index.html`, a strict CSP header whose `connect-src` adds only the origins of the API URL `VITE_API_URL` and the map URLs `VITE_MAP_STYLE_URL`, `VITE_MAP_TILES_URL` and `VITE_MAP_GLYPHS_URL`, read at start; MapLibre's worker is served from `'self'`, so no blob worker is allowed). `--dev-server=<url>` loads the Vite dev server, only when unpackaged and only on loopback HTTP (`electron/navigation.ts`).
- `electron/identity/` (S02, ADR 0021, ADR 0024): `installation.ts` (the installation's clinic registrations, never two to one clinic, each with its Ed25519 device key and its members' user keys; the PIN unwraps a member's key, and five wrong ones in a row, counted and written before the PIN is checked, disable it until an online password sign-in; the 7-day offline window measured from the later of the device clock and the highest time seen, carried forward by the monotonic clock from the highest time seen when the app starts, enforced during the session (checked every 30 seconds and on wake: the member is locked and the renderer told), and the clock warning; the unlocked member and their session tokens in memory, so a reload of the window keeps them, the refresh token never leaving the main process; the requests to the API whose answers change what a member may do (register, enroll, open and refresh the session, the password sign-in that re-enables a PIN, `GET /api/devices/current`), made by the main process itself with its own device tokens, outside the call queue; a registration or enrollment whose answer comes back after a lock, an unlock or a clinic switch stores the member but unlocks nobody (an identity generation); `DEVICE_REVOKED` and `ENROLLMENT_REVOKED` acted on there only, never on the renderer's word; the wipe of one registration, its device key kept until the server confirms the main process's own `POST /api/devices/current/wiped`; a PIN re-enabled with the member's phone as `GET /api/devices/current` lists it now; calls run one at a time), `keys.ts` (Ed25519, and the user key wrapped by Argon2id 64 MiB / 3 passes and then by `safeStorage`), `state-file.ts` (one file in `userData/identity/`, sealed whole by `safeStorage`, replaced atomically), `server.ts` (the main process's requests to the API at `VITE_API_URL`'s origin, answers checked with the contracts' schemas, refusals as `ServerRefusal` codes), `ipc.ts` (every call's input checked with Zod, refusals answered as codes only, the API's code as `REFUSED` with `refusal`), `bridge.ts` (the calls' types, shared by the renderer, the preload and the E2E). Without a real keystore (`safeStorage` unavailable, Linux `basic_text`) every call answers `STORAGE_UNAVAILABLE`.
- Configuration, read at build by Vite and at start by the main process: `VITE_API_URL` (the API's origin; unset, requests go to the renderer's own origin, which only the E2E uses) and the `VITE_MAP_*` URLs (`packages/ui/CLAUDE.md`).
- Unit tests sit next to the code (`electron/identity/test-support.ts`: a stand-in protector, a state store in memory, a cheap Argon2id cost, `testServer`: the API's identity routes in memory for the main process); `test/` holds the generated-client drift test. `e2e/`: Playwright against `vite preview`, at desktop (light and dark), tablet and phone sizes (`e2e/nav.ts` opens the phone's navigation sheet and the member menu). The API is mocked in memory by `e2e/mock-api.ts` (the S01 routes, bodies validated with the contracts, every staff route behind a session), `e2e/mock-identity.ts` (the S02 sign-in, device and session routes, signatures checked) and `e2e/mock-staff.ts` (staff, doctor profiles, device management and security, with the owner-only and `devices.manage` checks); the device bridge by `e2e/device-bridge.ts`, which runs the main process's own `Installation` in the test's process with a clock the test moves, its requests answered by `mock-identity.ts` in the same process (`identityTransport`) while the page is online, and its events sent to the page. `mockApi` signs the owner in on the device before the page opens unless `signedIn: false`; offline (`context.setOffline`), its routes answer nothing, as the bridge's. The preview server stands in for the app's local files: let a screen render before going offline, or its code fails to load. `e2e/settle.ts`'s `settled(page)` waits until no fetch or bridge call is open and the layout is still: `screenshot` calls it, and a test calls it before measuring boxes or going offline (never after `page.clock.install`). The E2E serves the build on 4173 on CI and on a free port locally, never reusing a running server (another worktree's).

## Rules
- Forms follow `packages/ui/CLAUDE.md` "Forms": `Form` + `FormFields` + `FormActions`, values in `useDraft`, Save disabled until a change with "Discard changes" beside it, `useUnsavedChangesGuard(dirty)` with its `dialog` rendered in the screen (`allowLeaving()` before a navigation the form starts after saving), success as a toast, notices under the actions. Every sub-page has a back action in its `PageHeader`.
- Closing or reloading the window with unsaved changes: the renderer holds `beforeunload`, and the main process asks "Stay" or "Leave without saving" on `will-prevent-unload` (`electron/unsaved-changes.ts`, texts from `packages/i18n`).
- Every text through i18next with keys from `packages/i18n` (`useTranslation('<namespace>')`); never a literal in a component. Numbers and dates through `Intl` with `formatLocale` from `@vertex-shifa/i18n` (Latin digits); times shown in `Asia/Damascus`.
- Design-system components and Tailwind utilities on semantic tokens only (`bg-surface`, `text-muted-foreground`); logical directions only (`ms-`, `pe-`, `start-`, `text-start`; in CSS `margin-inline-*`, `inline-size`…), no physical 3- or 4-value shorthands, no `translateX`, no color values: pinned by `packages/ui/src/conventions.test.ts`, which scans this app's `src/`. The window title comes from i18n too (`document.title`). Styles and fonts are files from `'self'`, so the CSP stays strict.
- Every screen has its loading, empty, error and offline states (ADR 0020). An error state never shows or logs the error's message: it may carry patient data (ADR 0016). `main.tsx` routes React's and the router's error hooks to `logErrorLabel` and redacts any `Error` passed to `console.error`/`console.warn`; log errors with `logErrorLabel`, never the error object or its message.
- The renderer is untrusted: it gets no Node access. Keys, the PINs' derived keys and (S04) the local database and sync live in the main process; the renderer reaches them only through the device bridge (ADR 0021), sending PINs, passwords and tickets in and getting public keys, signatures, views and access tokens out. A security transition (a session, a confirmation, a PIN re-enabled, a member's enrollment) happens only on an answer the main process got from the API itself: never on a session, a flag or a server answer the renderer sends. A new call is a method in `electron/identity/bridge.ts` with its Zod input in `ipc.ts`. Never loosen `contextIsolation`, `sandbox` or the CSP; a new origin (API, sync service) is added to `connect-src` explicitly.
- Identity: a ticket or a PIN never goes in a URL, on disk or in a log (the sign-in in progress lives in `flow.ts` memory). Signing in, registering, enrolling, "Forgot PIN" and re-enabling a PIN are online only; the PIN within the window, the idle lock and switching clinic work offline. One installation holds several clinics and members, and one member's server state never reaches another's screens: `remember` (and the installation query at start) moves the identity scope (`lib/identity-scope.ts`) whenever the unlocked member changes (lock, unlock, another clinic, a removed member, a wipe), which stops the previous member's requests, mutations and the code awaiting them before anything of the next one shows, and forgets their server state. So screens call the server through `api` and the query client, put callbacks in `useMutation`'s options (never in `mutate`'s second argument), wrap a callback's await of the identity layer or the device bridge in `withinScope(identityScope(), …)` taken before it, and keep `identityApi` to the identity layer (a request made for a given session carries that session's `authorization`, which the client keeps), whose answers concern the registration or member they were made for whoever is unlocked.
- Data comes from the local database and changes go through sync commands (ADR 0008). Configuration that changes only online (S01 setup) is server state through TanStack Query: while offline, queries pause, saving is disabled and nothing is queued. A refusal is shown by its code's text (`useErrorText`), never the server's message.
- An edit sends the `updatedAt` the form started from, not the latest one in the cache, so a background refetch never hides another editor's change; on `CONFLICT` the form reloads the record and says so.
- A save never waits for the connection: mutations run with `networkMode: 'always'` (`query-client.ts`), and a read inside a save uses `fetchNow`, so offline it fails at once and nothing is sent later on its own. A form is locked while its save runs, and the save's callbacks use the step and values it was sent with.
- A create whose answer was lost may have happened. The next save looks for it, and a record it finds is only shown to the owner, never overwritten on a guess: the owner saves again against its `updatedAt`. (An idempotent create with an id made on the device would remove the guess.)
- A change to `apps/api/openapi.json` fails `test/api-schema.test.ts` until the types are regenerated: `pnpm --filter @vertex-shifa/clinic exec vitest run -u test/api-schema.test.ts`.
- UI changes add or update the E2E RTL screenshots (desktop light and dark, tablet, phone) and are looked at before the PR. The window's minimum is 360 × 480 px (`electron/main.ts`): every screen fits it.

Run: `pnpm --filter @vertex-shifa/clinic test` · E2E (after `build`): `pnpm --filter @vertex-shifa/clinic test:e2e` · dev: `pnpm --filter @vertex-shifa/clinic dev` (browser: the "desktop app only" state) and `pnpm --filter @vertex-shifa/clinic dev:electron` (Electron on the dev server) · built app: `pnpm --filter @vertex-shifa/clinic start`.
