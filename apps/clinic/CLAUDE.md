# apps/clinic

Vertex Shifa Clinic, the offline-first desktop app (ADR 0008, ADR 0021, layout ADR 0020): a React + Vite + TanStack Router renderer in an Electron shell, Arabic-first RTL (ADR 0018). Today it holds the online-only clinic setup screens of S01 (onboarding wizard, clinic and branch settings); no local database, sync client, preload API or packaging yet (S04 and its specs bring them).

## Layout
- `src/main.tsx` mounts the router (routes preload on intent), TanStack Query and i18n; `src/routes/` holds thin file-based routes (TanStack Router; `src/routeTree.gen.ts` is generated by the Vite plugin on `dev` and `build`, committed, never edited or read); `__root.tsx` sets the shell, the tenant gate and the error and not-found states.
- `src/features/<area>/`: the components, queries and forms of one area. The pattern to copy for an online-only screen is S01: `features/tenancy/` (`queries.ts`: query options and API calls; `tenant-gate.tsx`: the tenant loaded before any screen, `/setup` while onboarding, the read-only banner and the main navigation; the shared field groups and their pure draft rules with unit tests), `features/setup/` (the wizard) and `features/settings/` (forms that keep the `updatedAt` they started from and reload on `CONFLICT`).
- App-wide `src/components/` (shell, `query-states.tsx`: loading, offline and error states of a screen's queries; `offline-notice.tsx`; `field-group.tsx`) and `src/lib/`: `i18n.ts`; `error-logging.ts` (errors logged by name only); `api.ts` (the typed `openapi-fetch` client and `unwrap`, which turns a refusal into an `ApiError` carrying its code only); `api-schema.gen.ts` (the API's types, generated from `apps/api/openapi.json` by `test/api-schema.test.ts`, committed, never edited or read); `error-text.ts` (a code's Arabic text); `query-client.ts`; `online.ts`; `map-config.ts` (the location picker's map from `VITE_MAP_*`, MapLibre's worker served as a file of the app); `staff-access.ts` (what the screens show per permission; every screen is the owner's until S02 reads the session).
- `src/styles.css`: imports Tailwind CSS and the design system (`@vertex-shifa/ui/styles.css`, ADR 0018); the app holds no colors or spacing of its own. Components and the `VertexShifaMark` come from `@vertex-shifa/ui`; `components/state-card.tsx` is the card of the screen states. The favicon comes from `brand/logo/svg/` (`index.html`).
- `electron/main.ts`: the main process. One window with `contextIsolation`, `sandbox`, no `nodeIntegration` and no preload; new windows, webviews and navigation outside the renderer's origin refused; every permission denied; one instance only. The built renderer is served from `app://clinic/` (`electron/app-protocol.ts`, path containment, client routes get `index.html`, a strict CSP header whose `connect-src` adds only the origins of the API URL `VITE_API_URL` and the map URLs `VITE_MAP_STYLE_URL`, `VITE_MAP_TILES_URL` and `VITE_MAP_GLYPHS_URL`, read at start; MapLibre's worker is served from `'self'`, so no blob worker is allowed). `--dev-server=<url>` loads the Vite dev server, only when unpackaged and only on loopback HTTP (`electron/navigation.ts`).
- Configuration, read at build by Vite and at start by the main process: `VITE_API_URL` (the API's origin; unset, requests go to the renderer's own origin, which only the E2E uses) and the `VITE_MAP_*` URLs (`packages/ui/CLAUDE.md`).
- Unit tests sit next to the code; `test/` holds the generated-client drift test. `e2e/`: Playwright against `vite preview`, light and dark, with the API mocked in memory by `e2e/mock-api.ts` (the S01 routes, bodies validated with the contracts) until sessions (S02) let it reach the real one.

## Rules
- Every text through i18next with keys from `packages/i18n` (`useTranslation('<namespace>')`); never a literal in a component. Numbers and dates through `Intl` with `formatLocale` from `@vertex-shifa/i18n` (Latin digits); times shown in `Asia/Damascus`.
- Design-system components and Tailwind utilities on semantic tokens only (`bg-surface`, `text-muted-foreground`); logical directions only (`ms-`, `pe-`, `start-`, `text-start`; in CSS `margin-inline-*`, `inline-size`…), no physical 3- or 4-value shorthands, no `translateX`, no color values: pinned by `packages/ui/src/conventions.test.ts`, which scans this app's `src/`. The window title comes from i18n too (`document.title`). Styles and fonts are files from `'self'`, so the CSP stays strict.
- Every screen has its loading, empty, error and offline states (ADR 0020). An error state never shows or logs the error's message: it may carry patient data (ADR 0016). `main.tsx` routes React's and the router's error hooks to `logErrorLabel` and redacts any `Error` passed to `console.error`/`console.warn`; log errors with `logErrorLabel`, never the error object or its message.
- The renderer is untrusted: it gets no Node access. The local database and sync live in the main process and the renderer reaches them only through a narrow IPC API in a preload (ADR 0021), added with S04. Never loosen `contextIsolation`, `sandbox` or the CSP; a new origin (API, sync service) is added to `connect-src` explicitly.
- Data comes from the local database and changes go through sync commands (ADR 0008). Configuration that changes only online (S01 setup) is server state through TanStack Query: while offline, queries pause, saving is disabled and nothing is queued. A refusal is shown by its code's text (`useErrorText`), never the server's message.
- An edit sends the `updatedAt` the form started from, not the latest one in the cache, so a background refetch never hides another editor's change; on `CONFLICT` the form reloads the record and says so.
- A save never waits for the connection: mutations run with `networkMode: 'always'` (`query-client.ts`), and a read inside a save uses `fetchNow`, so offline it fails at once and nothing is sent later on its own. A form is locked while its save runs, and the save's callbacks use the step and values it was sent with.
- A create whose answer was lost may have happened. The next save looks for it, and a record it finds is only shown to the owner, never overwritten on a guess: the owner saves again against its `updatedAt`. (An idempotent create with an id made on the device would remove the guess.)
- A change to `apps/api/openapi.json` fails `test/api-schema.test.ts` until the types are regenerated: `pnpm --filter @vertex-shifa/clinic exec vitest run -u test/api-schema.test.ts`.
- UI changes add or update the E2E RTL screenshots (light and dark) and are looked at before the PR.

Run: `pnpm --filter @vertex-shifa/clinic test` · E2E (after `build`): `pnpm --filter @vertex-shifa/clinic test:e2e` · dev: `pnpm --filter @vertex-shifa/clinic dev` (browser) and `pnpm --filter @vertex-shifa/clinic dev:electron` (Electron on the dev server) · built app: `pnpm --filter @vertex-shifa/clinic start`.
