# apps/clinic

Vertex Shifa Clinic, the offline-first desktop app (ADR 0008, ADR 0021, layout ADR 0020): a React + Vite + TanStack Router renderer in an Electron shell, Arabic-first RTL (ADR 0018). Today it is the shell only: no local database, sync client, preload API or packaging yet (S04 and its specs bring them).

## Layout
- `src/main.tsx` mounts the router and i18n; `src/routes/` holds thin file-based routes (TanStack Router; `src/routeTree.gen.ts` is generated by the Vite plugin on `dev` and `build`, committed, never edited or read); `__root.tsx` sets the shell and the error and not-found states.
- `src/features/<area>/`: the components, queries and forms of one area; the pattern to copy is `features/home/`. App-wide `src/components/` (shell, states) and `src/lib/` (`i18n.ts`; `error-logging.ts`: errors logged by name only).
- `src/styles.css`: imports Tailwind CSS and the design system (`@vertex-shifa/ui/styles.css`, ADR 0018); the app holds no colors or spacing of its own. Components and the `VertexShifaMark` come from `@vertex-shifa/ui`; `components/state-card.tsx` is the card of the screen states. The favicon comes from `brand/logo/svg/` (`index.html`).
- `electron/main.ts`: the main process. One window with `contextIsolation`, `sandbox`, no `nodeIntegration` and no preload; new windows, webviews and navigation outside the renderer's origin refused; every permission denied; one instance only. The built renderer is served from `app://clinic/` (`electron/app-protocol.ts`, path containment, client routes get `index.html`, a strict CSP header). `--dev-server=<url>` loads the Vite dev server, only when unpackaged and only on loopback HTTP (`electron/navigation.ts`).
- Unit tests sit next to the code. `e2e/`: Playwright against `vite preview`, light and dark.

## Rules
- Every text through i18next with keys from `packages/i18n` (`useTranslation('<namespace>')`); never a literal in a component. Numbers and dates through `Intl` with `formatLocale` from `@vertex-shifa/i18n` (Latin digits); times shown in `Asia/Damascus`.
- Design-system components and Tailwind utilities on semantic tokens only (`bg-surface`, `text-muted-foreground`); logical directions only (`ms-`, `pe-`, `start-`, `text-start`; in CSS `margin-inline-*`, `inline-size`…), no physical 3- or 4-value shorthands, no `translateX`, no color values: pinned by `packages/ui/src/conventions.test.ts`, which scans this app's `src/`. The window title comes from i18n too (`document.title`). Styles and fonts are files from `'self'`, so the CSP stays strict.
- Every screen has its loading, empty, error and offline states (ADR 0020). An error state never shows or logs the error's message: it may carry patient data (ADR 0016). `main.tsx` routes React's and the router's error hooks to `logErrorLabel` and redacts any `Error` passed to `console.error`/`console.warn`; log errors with `logErrorLabel`, never the error object or its message.
- The renderer is untrusted: it gets no Node access. The local database and sync live in the main process and the renderer reaches them only through a narrow IPC API in a preload (ADR 0021), added with S04. Never loosen `contextIsolation`, `sandbox` or the CSP; a new origin (API, sync service) is added to `connect-src` explicitly.
- Data comes from the local database and changes go through sync commands (ADR 0008); TanStack Query arrives with the first online-only screen.
- UI changes add or update the E2E RTL screenshots (light and dark) and are looked at before the PR.

Run: `pnpm --filter @vertex-shifa/clinic test` · E2E (after `build`): `pnpm --filter @vertex-shifa/clinic test:e2e` · dev: `pnpm --filter @vertex-shifa/clinic dev` (browser) and `pnpm --filter @vertex-shifa/clinic dev:electron` (Electron on the dev server) · built app: `pnpm --filter @vertex-shifa/clinic start`.
