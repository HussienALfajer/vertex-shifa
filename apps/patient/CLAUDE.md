# apps/patient

The Vertex Shifa patient app for Android and iOS (ADR 0003, layout ADR 0020): React Native + Expo (SDK 57, managed workflow) with Expo Router, Arabic-first RTL (ADR 0018). Today it is the shell only: no API calls, sign-in, secure storage, read cache or push yet. S19 brings the account, family, discovery, booking and notifications.

## Layout
- `app.config.ts`: the app name from the catalog, RTL forced natively (`extra.forcesRTL`, read by `expo-localization`), the sitemap route off. Store identifiers, the EAS project and icons arrive with the first store build. `android/` and `ios/` are generated by prebuild and git-ignored.
- `src/app/`: thin Expo Router routes. `_layout.tsx` runs the start-up (redacted console and uncaught-error handler, `forceRightToLeft`), sets the providers and the shell and exports the `ErrorBoundary`; `index.tsx` re-exports a feature's screen; `+not-found.tsx` is the not-found state; `+html.tsx` is the document of the web export.
- `src/features/<area>/`: the screens, queries and forms of one area; the pattern to copy is `features/home/`. App-wide `src/components/` (shell, state card, states) and `src/lib/` (`i18n.ts`; `error-logging.ts`: errors logged by name only; `rtl.ts`). The theme comes from `@vertex-shifa/ui-native` (`ThemeProvider` in `_layout.tsx`).
- Unit tests sit next to the code and import no React Native runtime (Vitest runs in Node). `e2e/`: Playwright against the web export.
- The web export (`dist/` from `pnpm build`, with the Android and iOS bundles) exists only for the E2E screenshots, served by `e2e/web-server.ts` on port 4176; the app is never hosted on the web (no PWA, ADR 0003). Dev server: 5176.

## Rules
- Every text through i18next with keys from `packages/i18n` (`useTranslation('<namespace>')`, this app's namespace is `patient`); never a literal in a component. Numbers and dates through `Intl` with `formatLocale` from `@vertex-shifa/i18n` (Latin digits); times shown in `Asia/Damascus`.
- Logical style properties only (`marginInlineStart`, `paddingBlock`, `insetInlineEnd`, `textAlign: 'auto'`, `flexDirection: 'row'`, which follows the direction), no `Left`/`Right`/`Top`/`Bottom` properties, `Horizontal`/`Vertical` shorthands or `translateX`: pinned by `packages/ui-native/test/conventions.test.ts`, which scans this app's `src/`.
- Colors, spacing, radii and type sizes through `useTheme()` from `@vertex-shifa/ui-native` (the Vertex tokens, ADR 0018), never a literal in a component; `Button` and `Card` from there too. System fonts for now.
- Every screen has its loading, empty, error and offline states (ADR 0020). An error state never shows or logs the error's message: it may carry patient data (ADR 0016). Log errors with `logErrorLabel`, never the error object or its message; no crash reporter receives a message.
- The app shows a patient only the items a clinic shared (ADR 0006, 0016). Booking needs a connection; the read cache and tokens in secure storage arrive with S19 (ADR 0003). Validation through `packages/contracts`.
- Push is Expo notifications plus the native token, tested on development builds, never Expo Go (ADR 0022). Service-account keys and `google-services.json` never enter the repository.
- Versions of Expo packages come from `pnpm exec expo install <package>`, which matches the SDK.
- UI changes add or update the E2E RTL screenshots (light and dark) and are looked at before the PR.

Run: `pnpm --filter @vertex-shifa/patient test` · E2E (after `build`): `pnpm --filter @vertex-shifa/patient test:e2e` · dev: `pnpm --filter @vertex-shifa/patient dev`.
