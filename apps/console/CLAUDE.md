# apps/console

The platform console, Vertex Shifa's back office for platform staff (layout ADR 0020): a React + Vite + TanStack Router web app, Arabic-first RTL (ADR 0018). Today it holds the console identity of S02 (spec S02 rules 36–41, screens 12–15): sign-in with the password and a TOTP or a recovery code, the setup of a new or reset user (setup code, password, authenticator QR, recovery codes shown once), the re-authentication dialog, platform users (admins) and my account. S22 brings the tenant, catalog, contract, billing, entitlement, account recovery and support-access screens.

## Layout
- `src/main.tsx` mounts the router, TanStack Query, the `Toaster` and i18n, and wires the end of the session into the API client (`startSession`); `src/routes/` holds thin file-based routes (TanStack Router; `src/routeTree.gen.ts` is generated by the Vite plugin on `dev` and `build`, committed, never edited or read); `__root.tsx` sets the session gate and the error and not-found states.
- `src/features/<area>/`: the components, queries and forms of one area. `features/session/` (S02): `session.ts` (`meQuery`, `signedIn` and `forgetSession`, `signOut`, `startSession`, `needsReauth`, `holds`), `session-gate.tsx` (every screen but `/sign-in` needs a session; the shell with the console's sidebar and the user menu: account and sign-out), `sign-in-api.ts` and `sign-in-screen.tsx` (screen 12; the steps' tickets stay in the screen's memory), `reauth.tsx` (screen 13: `ReauthProvider` and `useReauth`), `password-hints.tsx`. `features/platform-users/` (screen 14: `queries.ts` and the screen with its dialogs) and `features/account/` (screen 15). The pattern to copy for a screen is `features/platform-users/`.
- App-wide `src/components/` (`app-shell.tsx`: `AppShell`, the `AppFrame` of a signed-in user, and `AuthShell`, the `AuthFrame` of the sign-in and the error state; `state-card.tsx`, `query-states.tsx`: loading, offline and error states of a screen's queries, `offline-notice.tsx`) and `src/lib/`: `i18n.ts`; `error-logging.ts` (errors logged by name only); `api.ts` (the typed `openapi-fetch` client on the console's own origin, `unwrap`, which turns a refusal into an `ApiError` carrying its code only, and `watchSession`); `api-schema.gen.ts` (the API's types, generated from `apps/api/openapi.json` by `test/api-schema.test.ts`, committed, never edited or read); `error-text.ts` (a code's Arabic text); `proof-of-work.ts` (the sign-in's proof of work through Web Crypto); `query-client.ts`; `online.ts`; `format.ts` (dates and times in `Asia/Damascus` with Latin digits).
- `src/styles.css`: imports Tailwind CSS, the desktop typefaces (`@vertex-shifa/ui/fonts-desktop.css`) and the design system (`@vertex-shifa/ui/styles.css`, ADR 0018); `vite.config.ts` adds `vertexShifaWeb()` (the theme before the first paint, the fonts preloaded) and, in development, forwards `/api` to the local API (`API_PORT`, 3000 by default); every page sits in `PageContainer`; the app holds no colors or spacing of its own. Components, `CodeField`, `QrCode` and the `VertexShifaMark` come from `@vertex-shifa/ui`. The shell and states copy `apps/clinic`; the favicon comes from `brand/logo/svg/` (`index.html`).
- Unit tests sit next to the code; `test/` holds the generated-client drift test. `e2e/`: Playwright against `vite preview`, at desktop (light and dark), tablet and phone sizes (`e2e/nav.ts` opens the phone's navigation sheet and the user menu); the API is mocked in memory by `e2e/mock-api.ts` (the console routes, bodies validated with the contracts, the proof of work checked, single-use tickets, the session, the re-authentication window, the admin, self and last-admin rules; every authenticator shows `totpCode`). `mockConsoleApi(page, { signedIn })` starts with a session.
- Ports: dev 5174, preview 4174 (the clinic uses 5173 and 4173). The E2E serves the build on 4174 on CI and on a free port locally, never reusing a running server (another worktree's), so every E2E run goes side by side. The API's `CONSOLE_ORIGIN` is the dev server's origin by default: writes from another origin are refused.

## Rules
- Every text through i18next with keys from `packages/i18n` (`useTranslation('<namespace>')`, this app's namespace is `console`); never a literal in a component. Numbers and dates through `Intl` with `formatLocale` from `@vertex-shifa/i18n` (Latin digits); times shown in `Asia/Damascus`.
- Design-system components and Tailwind utilities on semantic tokens only (`bg-surface`, `text-muted-foreground`); logical directions only (`ms-`, `pe-`, `start-`, `text-start`; in CSS `margin-inline-*`, `inline-size`…), no physical 3- or 4-value shorthands, no `translateX`, no color values: pinned by `packages/ui/src/conventions.test.ts`, which scans this app's `src/`. The window title comes from i18n too (`document.title`).
- Every screen has its loading, empty, error and offline states (ADR 0020). An error state never shows or logs the error's message: it may carry tenant or patient data (ADR 0016). `main.tsx` routes React's and the router's error hooks to `logErrorLabel` and redacts any `Error` passed to `console.error`/`console.warn`; log errors with `logErrorLabel`, never the error object or its message.
- Authorization is server-side (ADR 0005): every console call goes to `/api/console/` routes that declare `@ConsoleRoute(permission)`; hiding a button or a screen (`holds`) is cosmetic. Support access opens a clinic's account only with the clinic's permission, for a limited time, audited (F39, S22); the console never holds medical data beyond what that access shows.
- The session is the API's `HttpOnly` cookie: the page never stores a token, a ticket, a setup code or a recovery code (not in a URL, storage or TanStack's caches: `signedIn` drops the recovery codes, and a mutation whose answer holds one runs with `gcTime: 0`). A request answered `UNAUTHENTICATED` or `SESSION_ENDED` clears the query and mutation caches (`forgetSession`) and opens `/sign-in` (`?ended=true` when a session was running); signing out does the same.
- A sensitive action (spec S02 rule 38: platform users, tenant status and directory, owner recovery, phone changes) runs inside `useReauth()`: it asks for a TOTP when `me` says the 5-minute window is closed, and again on `REAUTH_REQUIRED`; cancelling fails the action with `REAUTH_REQUIRED`. A recovery-code sign-in leaves the window closed.
- Server state through TanStack Query (`query-client.ts`): offline, queries pause, saving is disabled and nothing is queued (mutations run with `networkMode: 'always'`). A refusal is shown by its code's text (`useErrorText`), never the server's message.
- Forms follow `packages/ui/CLAUDE.md` "Forms": `Form` + `FormFields` + `FormActions`, success as a toast, notices under the actions.
- A change to `apps/api/openapi.json` fails `test/api-schema.test.ts` until the types are regenerated: `pnpm --filter @vertex-shifa/console exec vitest run -u test/api-schema.test.ts`.
- Security headers (CSP and the rest) are set by the host at the first deploy, which also serves the console and the API on one origin.
- UI changes add or update the E2E RTL screenshots (desktop light and dark, tablet, phone) and are looked at before the PR.

Run: `pnpm --filter @vertex-shifa/console test` · E2E (after `build`): `pnpm --filter @vertex-shifa/console test:e2e` · dev: `pnpm --filter @vertex-shifa/console dev`.
