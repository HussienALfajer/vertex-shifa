# apps/console

The platform console, Vertex Shifa's back office for platform staff (layout ADR 0020): a React + Vite + TanStack Router web app, Arabic-first RTL (ADR 0018). Today it is the shell only: no API calls, sign-in (console accounts with TOTP) or TanStack Query yet. S22 brings the tenant, catalog, contract, billing, entitlement and support-access screens.

## Layout
- `src/main.tsx` mounts the router and i18n; `src/routes/` holds thin file-based routes (TanStack Router; `src/routeTree.gen.ts` is generated by the Vite plugin on `dev` and `build`, committed, never edited or read); `__root.tsx` sets the shell and the error and not-found states.
- `src/features/<area>/`: the components, queries and forms of one area; the pattern to copy is `features/home/`. App-wide `src/components/` (shell, states) and `src/lib/` (`i18n.ts`; `error-logging.ts`: errors logged by name only).
- `src/styles.css`: imports Tailwind CSS and the design system (`@vertex-shifa/ui/styles.css`, ADR 0018); the app holds no colors or spacing of its own. Components and the `VertexShifaMark` come from `@vertex-shifa/ui`; `components/state-card.tsx` is the card of the screen states. The shell and states copy `apps/clinic`; the favicon comes from `brand/logo/svg/` (`index.html`).
- Unit tests sit next to the code. `e2e/`: Playwright against `vite preview`, light and dark.
- Ports: dev 5174, preview 4174 (the clinic uses 5173 and 4173), so both E2E servers run side by side.

## Rules
- Every text through i18next with keys from `packages/i18n` (`useTranslation('<namespace>')`, this app's namespace is `console`); never a literal in a component. Numbers and dates through `Intl` with `formatLocale` from `@vertex-shifa/i18n` (Latin digits); times shown in `Asia/Damascus`.
- Design-system components and Tailwind utilities on semantic tokens only (`bg-surface`, `text-muted-foreground`); logical directions only (`ms-`, `pe-`, `start-`, `text-start`; in CSS `margin-inline-*`, `inline-size`…), no physical 3- or 4-value shorthands, no `translateX`, no color values: pinned by `packages/ui/src/conventions.test.ts`, which scans this app's `src/`. The window title comes from i18n too (`document.title`).
- Every screen has its loading, empty, error and offline states (ADR 0020). An error state never shows or logs the error's message: it may carry tenant or patient data (ADR 0016). `main.tsx` routes React's and the router's error hooks to `logErrorLabel` and redacts any `Error` passed to `console.error`/`console.warn`; log errors with `logErrorLabel`, never the error object or its message.
- Authorization is server-side (ADR 0005): every console call goes to `/api/console/` routes that declare `@ConsoleRoute(permission)`; hiding a button is cosmetic. Support access opens a clinic's account only with the clinic's permission, for a limited time, audited (F39, S22); the console never holds medical data beyond what that access shows.
- Server state through TanStack Query, added with the first screen that calls the API. Security headers (CSP and the rest) are set by the host at the first deploy.
- UI changes add or update the E2E RTL screenshots (light and dark) and are looked at before the PR.

Run: `pnpm --filter @vertex-shifa/console test` · E2E (after `build`): `pnpm --filter @vertex-shifa/console test:e2e` · dev: `pnpm --filter @vertex-shifa/console dev`.
