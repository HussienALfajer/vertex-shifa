# apps/site

The public clinic pages (layout ADR 0020): a Next.js App Router app, Arabic-first RTL (ADR 0018), read by patients and visitors. Today it is the shell only: no API calls, tenant subdomains or custom domains yet. Phase 5 brings the clinic pages and public booking.

## Layout
- `src/app/`: thin App Router files. `layout.tsx` sets `<html lang dir>`, the page title (metadata from i18n) and the shell; `page.tsx` files re-export a feature's screen; `not-found.tsx`, `error.tsx` and `global-error.tsx` are the not-found and error states.
- `src/features/<area>/`: the components and data of one area; the pattern to copy is `features/home/`. App-wide `src/components/` (shell, states) and `src/lib/` (`i18n.ts`; `error-logging.ts`: errors logged by name only).
- `src/instrumentation.ts` (server) and `src/instrumentation-client.ts` (browser, before hydration) redact errors passed to `console.error`/`console.warn`.
- `src/styles.css`: imports Tailwind CSS and the design system (`@vertex-shifa/ui/styles.css`, ADR 0018); the app holds no colors or spacing of its own. Components and the `VertexShifaMark` come from `@vertex-shifa/ui`; `components/state-card.tsx` is the card of the screen states. Tailwind runs through PostCSS (`postcss.config.mjs`) and `next.config.ts` lists `@vertex-shifa/ui` in `transpilePackages`; the shell and states copy `apps/console`; the favicon is `brand/logo/svg/favicon.svg` through `metadata.icons`. Interactive design-system components are client components (`'use client'` in `packages/ui`); pages stay server components.
- Unit tests sit next to the code. `e2e/`: Playwright against `next start`, light and dark.
- Ports: dev 5175, `next start` 4175 (clinic 5173/4173, console 5174/4174), so every E2E server runs side by side. `next-env.d.ts` is generated by `next typegen`/`next build` and git-ignored.

## Rules
- Server components by default; `'use client'` only where Next.js or interaction needs it (error boundaries, later forms).
- Every text through the i18next instance in `src/lib/i18n.ts` with keys from `packages/i18n` (this app's namespace is `site`), used directly (`i18n.t`, `i18n.getFixedT(null, 'site')`), not through `react-i18next`: server components have no React context. Never a literal in a component; the title comes from the catalog through `metadata`. Numbers and dates through `Intl` with `formatLocale` from `@vertex-shifa/i18n` (Latin digits); times shown in `Asia/Damascus`.
- Design-system components and Tailwind utilities on semantic tokens only (`bg-surface`, `text-muted-foreground`); logical directions only (`ms-`, `pe-`, `start-`, `text-start`; in CSS `margin-inline-*`, `inline-size`…), no physical 3- or 4-value shorthands, no `translateX`, no color values: pinned by `packages/ui/src/conventions.test.ts`, which scans this app's `src/`.
- Every page has its loading, empty, error and offline states (ADR 0020). An error state never shows or logs the error's message: it may carry clinic or patient data (ADR 0016). Log errors with `logErrorLabel`, never the error object or its message.
- Public pages show only what a clinic chose to publish; medical data never reaches this app (ADR 0006, 0016). No fonts or scripts from third-party hosts (`next/font/google` fetches at build time); no Cloudflare (ADR 0015).
- No `X-Powered-By`; security headers (CSP and the rest) are set by the host at the first deploy.
- UI changes add or update the E2E RTL screenshots (light and dark) and are looked at before the PR.

Run: `pnpm --filter @vertex-shifa/site test` · E2E (after `build`): `pnpm --filter @vertex-shifa/site test:e2e` · dev: `pnpm --filter @vertex-shifa/site dev`.
